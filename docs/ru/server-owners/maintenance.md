# Обслуживание сервера

Как обслуживать уже работающий сервер BeamMP: файл журнала и обновление. Параметры `ServerConfig.toml` описаны на странице [Настройка сервера](/ru/server-owners/configuration).

## Файл журнала сервера

Этот файл создаётся при работе сервера. Он дублирует сообщения, которые вы видите в консоли при запуске сервера. Файл называется `Server.log`. При запуске сервер переименовывает журнал предыдущего запуска в `Server.old.log`, заменяя более старый `Server.old.log`. Прикладывайте этот файл каждый раз, когда обращаетесь за помощью к сотрудникам поддержки. В нём никогда не отображается ваш AuthKey, поэтому обычно его можно отправлять без изменений.

Формат такой (префикс $ означает «переменную», она объясняется ниже):

```
[$DATE $TIME] $CONTEXT [$LOG_LEVEL] $MESSAGE
```

Где:

- `$DATE` — дата сообщения в формате день/месяц/год, например 21/07/21
- `$TIME` — время сообщения, например 11:05:23. В режиме Debug показываются также миллисекунды, например 11:05:23.142
- `$CONTEXT` (виден только в режиме Debug и в основном важен разработчикам) — контекст сообщения, который может быть одним из двух:
	- `(Player ID) “Player Name”`, где ID игрока полезен для модерации
	- Короткое имя, например “HeartbeatThread”
- `$LOG_LEVEL` — один из уровней важности сообщения:
	- `DEBUG`: виден только в режиме Debug, обычно содержит много лишнего и важен только разработчикам
	- `EVENT`: виден только в режиме Debug, это событие Lua, которое вызвал сервер
	- `INFO`: общая информация
	- `LUA`: сообщение от Lua-плагина
	- `LUA WARN` и `LUA ERROR`: предупреждение или ошибка системы Lua-плагинов, например ошибка в коде плагина
	- `WARN`: описывает то, чего, как правило, не должно происходить
	- `ERROR`: что-то пошло очень не так или произошло совсем неожиданное
- `$MESSAGE` — само сообщение, обычно то, на что стоит обратить внимание и что нужно понять. Иногда оно может быть непонятным, но общее правило такое: если с сервером визуально всё в порядке и нет ERROR, значит, всё хорошо.

## Обновление сервера {#updating-the-server}

### Зачем обновлять

Когда выходит обновление, вам советуют обновить сервер. Обычно оно включает исправления ошибок, улучшения стабильности и безопасности, а также новые функции и многое другое.

Чтобы узнавать об обновлениях сразу после выхода, следите за каналом “update” на сервере Discord, ищите новости на форуме или смотрите (и спрашивайте) на [странице релизов GitHub](https://github.com/BeamMP/BeamMP-Server/releases).

### Как обновить

#### Если вы используете партнёрского хостинг-провайдера BeamMP

Если вы используете партнёрского хостинг-провайдера BeamMP, инструкции ниже, скорее всего, не подойдут. Мы рекомендуем дождаться подробностей от вашего хостинг-провайдера или обратиться к нему за помощью.

#### Если вы управляете сервером самостоятельно

Сервер обновляется заменой старого исполняемого файла новым. Если вы не уверены, как это сделать, ниже есть пошаговые инструкции для Windows и Linux.

Если вы собирали сервер из исходного кода, просто пересоберите его. Перед пересборкой обязательно выполните `git submodule update --init --recursive`.

#### В Windows

1. Убедитесь, что у вас установлены [распространяемые пакеты Visual C++](https://aka.ms/vs/17/release/vc_redist.x64.exe): они нужны для запуска сервера.
2. Перейдите на [BeamMP.com](https://beammp.com/) и нажмите кнопку “Download Server”.
3. После загрузки у вас появится один файл `BeamMP-Server.exe`. Назовём его «новым исполняемым файлом».
4. Перейдите в папку, где находится ваш текущий исполняемый файл `BeamMP-Server.exe` (обычно это та же папка, где лежит `ServerConfig.toml`). Назовём его «старым исполняемым файлом».
5. Замените старый исполняемый файл новым (например, скопировав или переместив новый файл в эту папку).

#### В Linux

1. Перейдите на [BeamMP.com](https://beammp.com/) и нажмите кнопку “Download Server”, вы будете перенаправлены на страницу релизов сервера на GitHub.
2. Скачайте файл для вашего дистрибутива и типа процессора. Его название выглядит как `BeamMP-Server.debian.12.x86_64`. Файлы `debuginfo` скачивать не нужно. Для простоты далее он называется `BeamMP-Server-xxx`, где `xxx` обозначает версию для используемого вами дистрибутива.
3. После загрузки у вас появится один файл `BeamMP-Server-xxx` (в зависимости от скачанной версии). Назовём его «новым исполняемым файлом».
4. Перейдите в папку, где находится ваш текущий исполняемый файл `BeamMP-Server-xxx` (обычно это та же папка, где лежит `ServerConfig.toml`). Назовём его «старым исполняемым файлом».
5. Замените старый исполняемый файл новым (например, скопировав или переместив новый файл в эту папку).
6. Откройте терминал в папке, где вы только что заменили исполняемый файл, и выполните `sudo chmod +x BeamMP-Server-xxx`. Это позволит запускать сервер.

### Сообщения об обновлениях

Сервер не обновляется сам. При запуске он проверяет, есть ли более новая версия, и выводит сообщение, если она есть. Затем он повторяет это сообщение с интервалом, который задаёт `UpdateReminderTime`, если только `ImScaredOfUpdates` не равно `true` (это значение по умолчанию). Оба параметра описаны в разделе [Настройка сервера](/ru/server-owners/configuration#the-misc-section). Хостинг-провайдер может заменить это сообщение: см. параметры провайдера в [руководстве по серверу](/ru/server-owners/manual#provider-settings).

Чтобы проверить наличие новой версии из скрипта, запросите у GitHub API последний релиз и сравните версию сервера с тегами. Получить их можно GET-запросом на `https://api.github.com/repos/BeamMP/BeamMP-Server/git/refs/tags`.
