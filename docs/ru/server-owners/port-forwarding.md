# Переадресация портов

::: danger ОТКАЗ ОТ ОТВЕТСТВЕННОСТИ:
**Переадресация портов — это риск**.

Переадресуя порты, вы осознаёте риски открытия портов вашей домашней сети для публичного доступа и тем самым лишаете себя права привлекать BeamMP к ответственности за **любой** ущерб, который может быть причинён вам или вашему домохозяйству.

Мы не несём ответственности за содержимое любых внешних сервисов и сайтов, на которые ведут ссылки.

<u>**Если вы не понимаете это руководство, рассмотрите возможность воспользоваться одним из наших партнёров.**</u>
:::

::: warning
Убедитесь, что ваш роутер не работает исключительно через 4G/5G. Если это гибридное устройство, позже в разделе 3 этого руководства обязательно выберите адаптер, подключённый по кабелю!
:::

## Что вам предстоит сделать

Создание правила переадресации портов связано с рядом сетевых терминов. Приготовьтесь записывать кое-что по ходу дела.

В этом руководстве 4 основных шага.

## Краткое руководство

1. **Назначьте статический IP-адрес вашему компьютеру или устройствам**

   Это нужно, чтобы IP-адрес устройства не менялся и не ломал правило переадресации портов.

   [Информация о вашем роутере](https://portforward.com/router.htm#1)

2. **Войдите в роутер**

   Обычно это делается так: найдите IP-адрес «Основной шлюз» (Default Gateway), выполнив `ipconfig` в командной строке, и введите его в адресную строку браузера.

3. **Переадресуйте порты на ваш компьютер**

   Найдите раздел переадресации портов в веб-интерфейсе роутера. На большинстве роутеров он находится в разделе Network, Advanced или LAN.

4. **Проверьте, что порт переадресован правильно**

   Используйте инструмент вроде CheckBeamMP, чтобы проверить, работает ли правило.

## Подробное руководство

### Назначение статического IP-адреса

#### Способ 1: резервирование DHCP

Другой способ задать статический IP-адрес в локальной сети — использовать функцию резервирования DHCP на вашем роутере. Не все роутеры её поддерживают, так что этот вариант может вам не подойти. Поищите в интернете руководство по модели вашего роутера. 

Если вам удалось это сделать, переходите к разделу [Вход в роутер](#log-in-to-your-router)

#### Способ 2: статический IP в Windows

##### Узнайте текущий IP-адрес, шлюз и DNS-серверы

Прежде чем задавать статический IP-адрес, нужно узнать ваши текущие сетевые настройки. 
Их стоит записать, так что приготовьте окно блокнота. 
На этом шаге мы будем использовать командную строку.

Откройте командную строку. Три основных способа:

- Нажмите клавишу Windows, начните вводить «cmd» и нажмите Enter, когда будет выделена «Командная строка».


<figure class="image image_resized" style="width:62%;">

![Меню «Пуск» Windows с выделенной командной строкой](../../assets/content/win11-open-cmd.png)

</figure>

В командной строке выполните следующую команду:
```
ipconfig /all
```
Вы увидите много данных.
Если у вас есть виртуальные адаптеры или несколько сетевых адаптеров, данных будет ещё больше. 
Обычно виртуальных адаптеров много, если установлены Hyper-V или Docker.

<figure class="image image_resized" style="width:62%;">

![Командная строка с выводом ipconfig, в котором выделены адрес IPv4, маска подсети, основной шлюз и DNS-серверы](../../assets/content/win11-command-prompt-ipconfig-highlighted.png)

</figure>

Рекомендуется использовать проводное сетевое подключение для компьютера, на котором будет работать сервер, но он будет работать и по беспроводному соединению.
В этом списке нужно найти адаптер с активным подключением к интернету. Прокрутите список и найдите тот, у которого задан основной шлюз. 
У многих виртуальных адаптеров основного шлюза нет. 

Ниже приведены примеры локальных адресов IPv4, и хотя бы у одного из адаптеров такой должен быть.
Вам нужно записать данные вашего адаптера.

- 192.168.x.x
- 10.x.x.x.
- 172.16.x.x - 172.31.x.x

Маска подсети (скорее всего, 255.255.255.0)
</br>
Основной шлюз (скорее всего, 192.168.0.1 или 192.168.1.1)

::: info Обратите внимание
BeamMP сейчас не поддерживает IPv6 для запуска сервера. 
:::

##### Измените настройки адаптера

Теперь нужно изменить настройки сетевого адаптера, чтобы компьютер сохранял текущую IP-конфигурацию. Самый быстрый способ открыть настройки сети:

- Один раз нажмите клавишу Windows
- Вводите «сетевые подключения», пока не увидите «Просмотр сетевых подключений»
- Нажмите Enter


<figure class="image image_resized" style="width:62%;">

![Меню «Пуск» Windows с пунктом «Просмотр сетевых подключений»](../../assets/content/win11-start-menu-view-network-connections.png)

</figure>

Вы увидите список сетевых подключений вашего компьютера. 
Если у вас установлены Hyper-V или Docker, их может быть много. 
Найдите адаптеры, названия которых не начинаются с «Hyper-V».

<figure class="image image_resized" style="width:62%;">

![Окно «Сетевые подключения» с адаптером Ethernet](../../assets/content/win11-network-connections.png)

</figure>


Щёлкните адаптер правой кнопкой мыши и выберите «Свойства». Если `Internet Protocol Version 4` не отмечен, это не тот адаптер. Выберите другой.

<figure class="image image_resized" style="width:62%;">

![Окно свойств Ethernet с выделенной записью IPv4](../../assets/content/win11-ethernet-properties-highlighted.png)

</figure>

Дважды щёлкните `Internet Protocol Version 4`. Переключите `Obtain an IP address automatically` на `Use the following IP address`.

Заполните IP-адрес, маску подсети, основной шлюз и предпочитаемый DNS-сервер данными из командной строки (ipconfig /all).

Вместо своих DNS-серверов можно также использовать DNS-серверы CloudFlare или Google:

- CloudFlare DNS: 1.1.1.1, 1.0.0.1
- Google DNS: 8.8.8.8, 8.8.4.4


<figure class="image image_resized" style="width:62%;">

![Окно свойств IPv4 с заполненными IP-адресом, маской подсети, основным шлюзом и DNS-серверами](../../assets/content/win11-network-settings-static-ip.png)

</figure>

Нажмите «ОК», затем ещё раз «ОК», и ваш адаптер переключится с DHCP на статический адрес. Откройте любой сайт, чтобы убедиться, что интернет по-прежнему работает. Если нет, верните настройку «Получить IP-адрес автоматически» и попробуйте следующий способ.

### Вход в роутер {#log-in-to-your-router}

Теперь, когда у вашего устройства статический IP-адрес, можно переадресовывать порт для BeamMP!

Для начала нужно войти в роутер. Ранее вы записали одну из настроек — основной шлюз. Это IP-адрес вашего роутера.

Большинство роутеров используют для управления локальную веб-страницу. Чтобы открыть меню и настройки роутера:

- Откройте браузер. Подойдут Firefox, Chrome или Edge.
- В адресной строке введите IP-адрес основного шлюза, например 192.168.0.1 или 192.168.1.1, и нажмите Enter

Вы увидите экран входа в роутер. Не все роутеры требуют вход, но большинство требует. Вам нужно знать имя пользователя и пароль роутера. Если вы ещё ни разу не входили, имя пользователя и пароль, скорее всего, заводские, а иногда указаны на наклейке на роутере.

Вот самые распространённые заводские имена пользователей и пароли:

| Имя пользователя | Пароль    |
| ---------------- | --------- |
| admin            | admin     |
| admin            | password  |
| {пусто}          | admin     |
| {пусто}          | password  |

Попробуйте разные сочетания admin, password и пустых значений. *Там, где написано «пусто», оставьте поле пустым.* 

### Создание правил переадресации

#### Поиск раздела переадресации

Найдите раздел переадресации портов в веб-интерфейсе роутера. Переходите по вкладкам и ссылкам вверху или слева на каждой странице. На большинстве роутеров этот раздел находится в Network, Advanced или LAN. Чтобы его найти, ищите такие ключевые слова:

- Port Forwarding
- Forwarding
- Port Range Forwarding
- Virtual Servers
- Apps & Gaming
- Advanced Setup/Settings
- NAT

#### Ввод данных

Найдя раздел переадресации портов своего роутера, введите нужные данные.
В роутере есть место, где указываются переадресуемые порты и IP-адрес назначения, на который они направляются. Если роутер показывает и внутренние, и внешние порты, сделайте их одинаковыми. 

BeamMP требует и UDP-, и TCP-порт 30814 (если вы не изменили его в [ServerConfig.toml](/ru/server-owners/host-a-server#configure-the-server)). 

::: info Примечание
Порт по умолчанию — **30814**, но можно выбрать любое другое число больше 1024 и меньше 65535. Если вы выбрали не 30814, запишите выбранное число. Переадресовать нужно и **TCP**, и **UDP**.
</br>
Рекомендуется оставить порт по умолчанию, поскольку он вряд ли будет использоваться другой службой на вашем компьютере.
</br>
Однако если вы запускаете несколько серверов на одном компьютере, у каждого сервера должен быть свой порт. Например, сервер 1: 30814, сервер 2: 30815.
:::

На некоторых роутерах нужно создать 2 правила, одно для UDP и одно для TCP, а на других можно сделать это одним правилом!

У большинства роутеров есть кнопка «Сохранить», а некоторым для вступления изменений в силу нужен перезапуск или перезагрузка.

Проверить подключение можно несколькими способами.

Мы рекомендуем использовать наш инструмент **CheckBeamMP**, так как он проверяет проблемы и протоколы, специфичные для BeamMP.

Для этого нужно узнать ваш публичный адрес IPv4, что тоже можно сделать несколькими способами. Основной способ — сайт [whatsmyip.org](https://whatsmyip.org/). Он просто показывает ваш публичный IP-адрес. Ищите IP-адрес в формате xxx.xxx.xxx.xxx

Перейдите по следующей ссылке, заменив «IP» своим адресом IPv4, а «Port» — портом вашего сервера. Не оставляйте пробелов.
https://check.beammp.com/api/v2/beammp/ip/port

::: success status: ok
Если вы получили такой ответ, вы можете подключаться к своему серверу!
Подключиться можно двумя способами: напрямую, с данными, которые вы ввели выше, или, если ваш сервер публичный, через список серверов.
Поскольку вы размещаете сервер у себя дома, используйте 127.0.0.1 (localhost), если сервер запущен на том же компьютере, на котором вы играете, или локальный IPv4-адрес компьютера, на котором запущен сервер.
:::

::: failure status: error
Если подключиться не удаётся совсем, возможно, ваш провайдер использует CGNAT (Carrier Grade Network Address Translation). Подробнее см. [Проверка CGNAT](/ru/server-owners/cgnat),
  или создайте тикет Server Support на нашем [сервере Discord](https://discord.gg/beammp) в канале `#support`, и кто-нибудь из персонала вам поможет!
  Если работает только TCP, а UDP нет, ещё раз проверьте правила брандмауэра и переадресации портов.
:::
