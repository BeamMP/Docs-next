# Вход через BeamMP

Эта страница для разработчиков, которые хотят, чтобы пользователи входили на их сайт или в приложение через аккаунт BeamMP. В итоге у вас будет работающий вход по OAuth 2.0, который возвращает ID аккаунта BeamMP, имя пользователя, аватар и, если пользователь разрешит, адрес электронной почты.

BeamMP использует поток OAuth 2.0 **authorization code** (код авторизации). Это только OAuth 2.0, а не OpenID Connect: здесь нет `id_token`, документа discovery и JWKS.

## Конечные точки

| Назначение | Метод и адрес |
|---|---|
| Авторизация (открывается в браузере пользователя) | `GET https://accounts.beammp.com/auth/external` |
| Обмен кода на токен | `POST https://api.beammp.com/v1/oauth/token` |
| Профиль пользователя | `GET https://api.beammp.com/v1/oauth/userinfo` |
| Отзыв токена | `POST https://api.beammp.com/v1/oauth/revoke` |

## Создайте приложение

Приложение создаётся в **консоли разработчика** (Developer Console) вашего аккаунта BeamMP на [accounts.beammp.com](https://accounts.beammp.com). Возможности для разработчиков включаются для каждого аккаунта отдельно и по умолчанию выключены. Чтобы получить их, обратитесь к команде BeamMP на [сервере Discord](https://discord.gg/beammp).

Вы указываете:

| Поле | Примечания |
|---|---|
| Название приложения | От 3 до 80 символов. Показывается пользователям, когда у них запрашивают подтверждение для вашего приложения. |
| Сайт | Необязательно. Полный адрес `https://` или `http://`. Показывается как ссылка на странице подтверждения. |
| URL политики конфиденциальности | Необязательно, но настоятельно рекомендуется. Полный адрес `https://` или `http://`. Показывается как ссылка на странице подтверждения, чтобы пользователи могли прочитать, что вы делаете с их данными, прежде чем дать согласие. Если вы его не укажете, на странице подтверждения будет сказано, что политика не предоставлена. |
| Описание | Необязательно. Показывается на странице подтверждения. |
| URI перенаправления | По одному на строку. Адреса `https://` или `http://` для `localhost` и `127.0.0.1` на время разработки. Пользовательские схемы не принимаются. |

Адреса сайта и политики конфиденциальности проверяются при сохранении. Принимаются только обычные адреса `http://` или `https://`: адреса `javascript:`, `data:` и `ftp:`, а также адреса с именем пользователя и паролем не допускаются.

После этого вы получаете **ID клиента** (client ID) и **секрет клиента** (client secret). Секрет показывается один раз, позже его можно заменить на новый.

::: warning Храните секрет на своём сервере
Никогда не помещайте секрет клиента в браузерное или мобильное приложение. Если ваше приложение не может хранить секрет, например одностраничное приложение (SPA), используйте вместо него [PKCE](#pkce).
:::

## Отправьте пользователя в BeamMP

Откройте этот адрес в браузере пользователя:

```
https://accounts.beammp.com/auth/external
  ?client_id=YOUR_CLIENT_ID
  &redirect_uri=https%3A%2F%2Fexample.com%2Fcallback
  &response_type=code
  &scope=profile%20email
  &state=RANDOM_VALUE
  &code_challenge=CHALLENGE
  &code_challenge_method=S256
```

| Параметр | Обязателен | Примечания |
|---|---|---|
| `client_id` | Да | Ваш ID клиента. |
| `redirect_uri` | Да | Должен в точности совпадать с одним из зарегистрированных вами URI перенаправления. |
| `response_type` | Да | Должен быть `code`. Другие значения не поддерживаются. |
| `scope` | Нет | Значения через пробел. По умолчанию `profile`. См. [Разрешения](#scopes). |
| `state` | Рекомендуется | Случайное значение, которое вы генерируете. Возвращается без изменений. Проверьте, что оно совпадает, чтобы защититься от поддельных обратных вызовов. |
| `code_challenge` | Рекомендуется | Проверочный код PKCE (challenge). См. [PKCE](#pkce). |
| `code_challenge_method` | Если есть challenge | Должен быть `S256`. `plain` не поддерживается. |

Пользователь входит в BeamMP, при необходимости вводя пароль и код двухфакторной аутентификации, если они требуются для его аккаунта. Затем он видит экран с названием вашего приложения, описанием, сайтом, ссылкой на политику конфиденциальности и запрошенными вами разрешениями. Он подтверждает или отклоняет запрос.

Если сам запрос недопустим, например приложение неизвестно, `redirect_uri` не зарегистрирован или указано неподдерживаемое разрешение, BeamMP показывает ошибку пользователю и не перенаправляет его в ваше приложение.

Аккаунты, которые заблокированы, деактивированы или ещё ожидают восстановления, ничего авторизовать не могут.

## Получите код

Когда пользователь подтверждает запрос, BeamMP перенаправляет его на ваш `redirect_uri`:

```
https://example.com/callback?code=AUTHORIZATION_CODE&state=RANDOM_VALUE
```

Если пользователь отклоняет запрос, вместо этого вы получите `?error=access_denied&state=RANDOM_VALUE`.

Код действителен 5 минут и может быть использован один раз. Неудачная попытка обменять его тоже расходует код, поэтому запросите новый код, а не повторяйте попытку.

## Обменяйте код на токен доступа

Вызывайте конечную точку токена со своего сервера. Отправляйте тело в формате `application/x-www-form-urlencoded`. JSON тоже принимается.

С секретом клиента и HTTP Basic-аутентификацией:

```bash
curl -X POST https://api.beammp.com/v1/oauth/token \
  -u "YOUR_CLIENT_ID:YOUR_CLIENT_SECRET" \
  -d grant_type=authorization_code \
  -d code=AUTHORIZATION_CODE \
  -d redirect_uri=https://example.com/callback \
  -d code_verifier=YOUR_VERIFIER
```

Или с учётными данными в теле запроса:

```bash
curl -X POST https://api.beammp.com/v1/oauth/token \
  -d grant_type=authorization_code \
  -d code=AUTHORIZATION_CODE \
  -d redirect_uri=https://example.com/callback \
  -d client_id=YOUR_CLIENT_ID \
  -d client_secret=YOUR_CLIENT_SECRET \
  -d code_verifier=YOUR_VERIFIER
```

`redirect_uri` должен совпадать со значением, которое вы отправили при открытии адреса авторизации. Отправьте `code_verifier`, если вы отправляли `code_challenge`.

Успешный ответ:

```json
{
  "access_token": "bmp_at_...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "profile email"
}
```

Токен доступа действует 1 час. Токенов обновления нет: когда срок действия токена истечёт, снова проведите пользователя через вход. Если у него всё ещё есть сессия BeamMP, это происходит быстро.

## Получите профиль пользователя

```bash
curl https://api.beammp.com/v1/oauth/userinfo \
  -H "Authorization: Bearer ACCESS_TOKEN"
```

```json
{
  "sub": "12345",
  "username": "Racer",
  "picture": "https://api.beammp.com/v1/avatars/abc123",
  "email": "racer@example.com",
  "email_verified": true
}
```

| Поле | Нужное разрешение | Примечания |
|---|---|---|
| `sub` | Любое | Постоянный ID аккаунта BeamMP пользователя в виде строки. Используйте его для идентификации аккаунта. |
| `username` | `profile` | Может меняться со временем. Не используйте его как ключ. |
| `picture` | `profile` | Адрес аватара пользователя или `null`. Его можно показывать на любом сайте. |
| `email` | `email` | Основной адрес электронной почты пользователя или `null`. |
| `email_verified` | `email` | Подтверждён ли этот адрес. |

BeamMP проверяет аккаунт при каждом вызове. Если пользователя заблокировали или деактивировали после того, как он подтвердил доступ вашему приложению, userinfo возвращает `401 invalid_token`, пока с его аккаунтом не будет всё в порядке.

## Отзовите токен

Когда пользователь отключает ваше приложение, отзовите его токен:

```bash
curl -X POST https://api.beammp.com/v1/oauth/revoke \
  -u "YOUR_CLIENT_ID:YOUR_CLIENT_SECRET" \
  -d token=ACCESS_TOKEN
```

Всегда возвращается `200 {}`, как описано в RFC 7009, в том числе для неизвестных и просроченных токенов. Отозвать можно только токены, выданные вашему приложению. Отправлять секрет необязательно, но если вы его отправляете, он должен быть верным.

## Разрешения {#scopes}

| Разрешение (scope) | Что вы получаете |
|---|---|
| `profile` (по умолчанию) | `sub`, `username`, `picture` |
| `email` | `email`, `email_verified` |

`openid` не поддерживается. Многие библиотеки OAuth добавляют его по умолчанию. Отключите это, иначе запрос будет остановлен с сообщением, в котором назван неподдерживаемый scope.

Запрашивайте только необходимое: пользователи видят каждое разрешение на экране подтверждения.

## Аутентификация клиента

Запрос токена можно аутентифицировать одним из двух способов:

- **Секрет клиента** — для веб-приложения с сервером. Используйте HTTP Basic или отправьте `client_id` и `client_secret` в теле запроса. Выберите один способ, но не оба сразу. Если вы используете Basic и при этом отправляете `client_id` в теле, он должен совпадать.
- **PKCE** — для приложений, которые не могут хранить секрет, или как дополнительная защита. Отправьте `code_challenge` при открытии адреса авторизации и `code_verifier` при обмене кода.

Запрос токена должен подтвердить хотя бы один из двух способов. Если вы отправили `code_challenge`, `code_verifier` проверяется всегда, даже если вы отправили и секрет. Неверный секрет отклоняется без расходования кода. Рекомендуется использовать PKCE вместе с секретом.

## PKCE {#pkce}

Поддерживается только метод `S256`.

- `code_verifier`: случайная строка из 43–128 символов из набора `A-Z a-z 0-9 - . _ ~`.
- `code_challenge`: хеш SHA-256 от verifier, закодированный в base64url без заполнения (padding). Его длина всегда 43 символа.

```js
import crypto from "node:crypto";

const verifier = crypto.randomBytes(32).toString("base64url");           // 43 characters
const challenge = crypto.createHash("sha256").update(verifier).digest("base64url");
// send `challenge` when you open the authorization address; keep `verifier` and send it when you exchange the code
```

## Ошибки

Ошибки конечных точек токена и отзыва возвращаются в виде JSON со стандартным кодом:

```json
{ "error": "invalid_grant", "error_description": "Authorization code is invalid, expired, or does not match this request" }
```

| `error` | Статус | Значение |
|---|---|---|
| `invalid_request` | 400 | Отсутствует обязательный параметр или использованы оба способа аутентификации клиента. |
| `invalid_client` | 401 | Неизвестный клиент, неверный секрет или нет ни секрета, ни PKCE. |
| `invalid_grant` | 400 | Код недействителен, просрочен, уже использован или не соответствует приложению или `redirect_uri`. Также: не пройдена проверка PKCE или аккаунт недоступен, например из-за блокировки. |
| `unsupported_grant_type` | 400 | Поддерживается только `authorization_code`. |
| `invalid_token` (userinfo) | 401 | Токен доступа недействителен, просрочен или отозван, либо его аккаунт недоступен. |

## Ограничения и сроки действия

| Элемент | Значение |
|---|---|
| Код авторизации | 5 минут, одноразовый |
| Токен доступа | 1 час |
| Конечные точки токена и отзыва | Неудачные запросы ограничены 30 в минуту на один IP-адрес. Успешные запросы не учитываются. |
| Конечная точка userinfo | 600 запросов в минуту на один IP-адрес |

## URI перенаправления

- URI перенаправления должен в точности совпадать с зарегистрированным: схема, хост, порт, путь и запрос.
- В рабочей среде используйте URI перенаправления с `https://`. `http://` принимается только для `localhost` и `127.0.0.1` на время разработки.

## Перед запуском в работу

- Укажите URL политики конфиденциальности, чтобы пользователи могли прочитать её до подтверждения.
- Генерируйте новое случайное значение `state` для каждого входа и проверяйте его, когда пользователь возвращается.
- Используйте PKCE, даже если у вас есть секрет клиента.
- Храните секрет клиента только на своём сервере.
- Идентифицируйте пользователей по `sub`, а не по `username` или `email`.
- Вызывайте конечную точку токена со своего сервера, а не из браузера.
- Не записывайте в журнал и не храните токены доступа дольше, чем нужно.
