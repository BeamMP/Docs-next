# Настройка среды разработки

Эта страница показывает, как настроить компьютер для работы над модом BeamMP и как запустить локальный сервер. Как связаны мод, лаунчер и сервер, см. в разделе [Разработчикам](/ru/developers/).

## Что вам понадобится

- BeamNG.drive, установленная локально.
- BeamMP, установленный локально: как минимум лаунчер, а также сервер, если вы хотите тестировать с ним.
- Git, установленный локально, и аккаунт GitHub.
- Редактор кода, например VSCode или Notepad++.

## Используйте распакованную папку для BeamNG

Чтобы эффективно работать с модами, используйте папку `unpacked` вместо того, чтобы после каждого изменения упаковывать zip-архив.

1. Откройте папку `mods` в пользовательской папке BeamNG. В Windows это `%LocalAppData%\BeamNG\BeamNG.drive\current\mods`. Лаунчер при запуске показывает используемую им папку в строке `Game user path:`.
2. Создайте в `mods` папку с именем `unpacked`.

Подробнее о пользовательской папке см. в [документации BeamNG](https://documentation.beamng.com/support/userfolder/).

## Включите режим разработчика в лаунчере {#turn-on-dev-mode-in-the-launcher}

Запустите лаунчер с аргументом `--dev`. Режим разработчика выводит отладочные сообщения, не скачивает мод BeamMP, не запускает BeamNG.drive и не обновляет лаунчер. Если вам нужна только часть этого, используйте отдельные параметры ниже.

Без `--no-download` лаунчер скачивает выпущенную версию мода BeamMP в `mods/multiplayer`. Кроме того, он удаляет `mods/unpacked/beammp`, если в этой папке нет папки `.git`. Используйте `--no-download`, чтобы выпущенная версия мода не работала рядом с вашей.

| Аргумент | Что делает |
|---|---|
| `--help`, `-h` или `/?` | Выводит этот список аргументов и закрывается |
| `--port <port>` или `-p <port>` | Меняет порт прослушивания, по умолчанию `4444`, на `<port>`. Лаунчер также использует `<port>` + 1. Его нужно задать и в игре. Заменяет `Port` в `Launcher.cfg` |
| `--verbose` или `-v` | Подробный режим: выводит отладочные сообщения в окне. В `Launcher.log` они записываются всегда |
| `--no-download` | Пропускает скачивание и установку мода BeamMP |
| `--no-update` | Пропускает применение обновлений лаунчера, поэтому обновлять его нужно вручную |
| `--no-launch` | Пропускает запуск игры, поэтому запускать её нужно самостоятельно |
| `--dev` | Режим разработчика: то же, что `--verbose --no-download --no-launch --no-update` |
| `--user-path <path>` | Только для Windows. Путь к пользовательской папке BeamNG.drive, то есть к папке, в которой находится `current` |
| `--game <args...>` или `-- <args...>` | Передаёт игре все аргументы, указанные после него |

### Файл настроек лаунчера

Лаунчер читает `Launcher.cfg` из папки, из которой он запущен. Если файла нет, лаунчер создаёт его с первыми тремя настройками. Параметры командной строки заменяют соответствующие настройки.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `"Port"` | `4444` | Порт, к которому подключается игра. См. [Изменение порта лаунчера](/ru/troubleshooting/launcher-port) |
| `"Build"` | `"Default"` | Сборка, которую лаунчер запрашивает у бэкенда BeamMP при проверке обновлений лаунчера и мода. Оставьте `Default` |
| `"CachingDirectory"` | `"./Resources"` | Папка, в которой лаунчер хранит скачанные моды серверов |
| `"Dev"` | не задано | `true` равносильно `--dev` |
| `"DeleteDuplicateMods"` | `false` | При `true` лаунчер удаляет старые кэшированные версии мода, когда сервер присылает более новую |

### Кэш модов

Когда вы подключаетесь к серверу, лаунчер скачивает каждый мод из списка сервера в папку `CachingDirectory`. Мод сохраняется как `<name>-<first 8 characters of its SHA-256 hash>.zip`. Лаунчер повторно использует кэшированный файл, если его хеш совпадает, и записывает время последнего использования каждого файла в `mods.json` в той же папке. Затем он копирует мод в `mods/multiplayer` в пользовательской папке игры, а в Linux делает имя файла строчными буквами.

При каждом запуске лаунчер удаляет всё в `mods/multiplayer`, кроме `beammp.zip`. Не храните там свои файлы.

## Соберите лаунчер

Собирать лаунчер нужно только в том случае, если вы работаете над самим лаунчером. В `README.md` лаунчера нет шагов сборки.

В Windows вам понадобятся Visual Studio с рабочей нагрузкой C++ для настольных приложений (MSVC), CMake и [vcpkg](https://github.com/microsoft/vcpkg). Библиотеки в `vcpkg.json`: `cpp-httplib`, `nlohmann-json`, `zlib`, `openssl` и `curl`. Лаунчер использует статическую среду выполнения C++, поэтому используйте триплет `x64-windows-static`. В корневой папке проекта выполните следующее. Замените `C:/vcpkg` на папку, в которую вы установили `vcpkg`:

```bash
cmake . -B bin -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-static
cmake --build bin --parallel --config Release
```

Программа находится по адресу `bin/Release/BeamMP-Launcher.exe`. В Windows лаунчер заменяет себя официальной подписанной версией, когда выходит более новая, поэтому свою сборку запускайте с `--no-update`.

Для Linux следуйте инструкции [Сборка лаунчера](/ru/get-started/install-beammp#build-the-launcher). В macOS лаунчер не собирается.

## Клонируйте репозиторий BeamMP в распакованную папку

Файлы мода можно скопировать из нашего репозитория на GitHub вручную, но система контроля версий, такая как git, намного удобнее.

1. Создайте форк [BeamMP/BeamMP](https://github.com/BeamMP/BeamMP).
2. Клонируйте его прямо в папку `unpacked`. В PowerShell или CMD, открытых в этой папке, выполните:

   ```bash
   git clone https://github.com/yourName/BeamMP
   ```

3. В пользовательской папке удалите `mods/multiplayer/beammp.zip`, если он есть. Обычный запуск лаунчера скачивает его, а `--no-download` его не удаляет. Убедитесь, что есть `mods/unpacked/beammp`.
4. Попробуйте режим разработчика. Запустите лаунчер с `--dev`, затем вручную запустите BeamNG. В игре убедитесь, что BeamMP — единственный активный мод. Вы можете пользоваться BeamMP как обычно.

Теперь в редакторе кода можно менять код прямо в папке `unpacked`. Перезагрузить Lua в игре можно с помощью `Ctrl` + `L`, а если вы меняли интерфейс, нажмите также `F5`.

## Настройте локальный сервер

Локальный сервер помогает при работе над BeamMP. Следуйте инструкции [Запуск сервера](/ru/server-owners/host-a-server), пропустив первые два шага (переадресацию портов и AuthKey), если вы подключаетесь только локально.

В `ServerConfig.toml` сделайте сервер приватным, а в качестве `AuthKey` используйте любую строку.

## Отправьте свои изменения

Когда вы довольны изменениями, зафиксируйте их с помощью git. На [сайте Git-SCM](https://git-scm.com/doc) есть учебные материалы и документация. Когда изменения зафиксированы и отправлены в ваш форк, можно создавать pull request.

В репозитории мода BeamMP есть файл `CONTRIBUTING.md` с форматом кода, форматом сообщений коммитов и общими практиками разработки. В репозитории лаунчера есть файл `.clang-format` со стилем кода, а шаблон его pull request просит подтвердить, что вы сами написали и понимаете весь код. В `README.md` репозитория могут быть описаны шаги сборки для компилируемых проектов.

Если возникнут проблемы, задайте вопрос в канале `#scripting` на нашем [сервере Discord](https://discord.gg/beammp).
