# Настройка среды разработки

Эта страница показывает, как настроить компьютер для работы над модом BeamMP и как запустить локальный сервер. Как связаны мод, лаунчер и сервер, см. в разделе [Разработчикам](/ru/developers/).

## Что вам понадобится

- BeamNG.drive, установленная локально.
- BeamMP, установленный локально: как минимум лаунчер, а также сервер, если вы хотите тестировать с ним.
- Git, установленный локально, и аккаунт GitHub.
- Редактор кода, например VSCode или Notepad++.

## Используйте распакованную папку для BeamNG

Чтобы эффективно работать с модами, используйте папку `unpacked` вместо того, чтобы после каждого изменения упаковывать zip-архив.

1. Откройте пользовательскую папку BeamNG по адресу `%appdata%/Local/BeamNG.drive/0.xx/mods`, где `xx` — самая свежая версия BeamNG.
2. Создайте в `mods` папку с именем `unpacked`.

Подробнее о пользовательской папке см. в [документации BeamNG](https://documentation.beamng.com/support/userfolder/).

## Включите режим разработчика в лаунчере

Автообновление удалило бы ваш локальный клон git, поэтому отключите его с помощью `--no-download`. Если вы также не хотите, чтобы лаунчер запускал BeamNG, и хотите видеть отладочный вывод, используйте `--dev`.

| Аргумент | Что делает |
|---|---|
| `--help` или `-h` | Выводит этот список аргументов |
| `--port <port>` или `-p` | Меняет порт прослушивания по умолчанию на `<port>`. Его нужно задать и в игре |
| `--verbose` или `-v` | Подробный режим: выводит отладочные сообщения |
| `--no-download` | Пропускает скачивание и установку Lua-мода BeamMP |
| `--no-update` | Пропускает применение обновлений лаунчера, поэтому обновлять его нужно вручную |
| `--no-launch` | Пропускает запуск игры, поэтому запускать её нужно самостоятельно |
| `--dev` | Режим разработчика: то же, что `--verbose --no-download --no-launch --no-update` |
| `--game <args...>` или `-- <args...>` | Передаёт аргументы игре |

## Клонируйте репозиторий BeamMP в распакованную папку

Файлы мода можно скопировать из нашего репозитория на GitHub вручную, но система контроля версий, такая как git, намного удобнее.

1. Создайте форк [BeamMP/BeamMP](https://github.com/BeamMP/BeamMP).
2. Клонируйте его прямо в папку `unpacked`. В PowerShell или CMD, открытых в этой папке, выполните:
   ```bash
   git clone https://github.com/yourName/BeamMP
   ```
3. В пользовательской папке убедитесь, что в `mods` не осталось папки `multiplayer` и что теперь есть `unpacked/beammp`.
4. Попробуйте режим разработчика. Запустите лаунчер, затем вручную запустите BeamNG. В игре убедитесь, что BeamMP — единственный активный мод. Вы можете пользоваться BeamMP как обычно.

Теперь в редакторе кода можно менять код прямо в папке `unpacked`. Перезагрузить Lua в игре можно с помощью `Ctrl` + `L`, а если вы меняли интерфейс, нажмите также `F5`.

## Настройте локальный сервер

Локальный сервер помогает при работе над BeamMP. Следуйте инструкции [Запуск сервера](/ru/server-owners/host-a-server), пропустив первые два шага (переадресацию портов и AuthKey), если вы подключаетесь только локально.

В `ServerConfig.toml` сделайте сервер приватным, а в качестве `AuthKey` используйте любую строку.

## Отправьте свои изменения

Когда вы довольны изменениями, зафиксируйте их с помощью git. На [сайте Git-SCM](https://git-scm.com/doc) есть учебные материалы и документация. Когда изменения зафиксированы и отправлены в ваш форк, можно создавать pull request.

О формате кода, формате сообщений коммитов и общих практиках разработки см. файл `CONTRIBUTING.md` в каждом репозитории. В `README.md` каждого репозитория обычно описаны шаги сборки для компилируемых проектов.

Если возникнут проблемы, задайте вопрос в канале `#scripting` на нашем [сервере Discord](https://discord.gg/beammp).
